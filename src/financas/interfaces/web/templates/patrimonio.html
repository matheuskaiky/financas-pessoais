Uso (em qualquer template): {% from "patrimonio.html" import patrimonio %} {{ patrimonio(points=serie, badge="parcial", footnote="Parcial: investimentos mais caixa, menos as faturas já fechadas.", empty_href=url_for("novo_saldo")) }} `serie` é uma lista de pares [data ISO, centavos inteiros], em qualquer ordem (o componente ordena): serie = [[d.isoformat(), cents] for d, cents in rows] # nunca float, nunca reais Duas formas de entregar os dados: · points=… → o JSON vai DENTRO do elemento (sem requisição extra; ideal para séries pequenas, como as de lançamento manual); · src="/api/patrimonio" → o componente busca na mesma origem (só mesma origem; qualquer outra é bloqueada). O que o servidor renderiza antes do JavaScript ligar (e que o componente troca ao subir): · o último saldo em texto, para quem tem JavaScript desligado ou a página ainda carregando; · a caixa já na altura final (regra `fp-patrimonio:not(:defined)` do fp-patrimonio.css): zero salto de layout. Moeda: o saldo que o servidor escreve sai pelo filtro `money` (fp_money.py), com símbolo, separadores e posição da divisa em vigor: nenhum "R$" fica escrito aqui. Requer `fp_money.install(templates.env)` uma vez, ao subir o app. No navegador a ilha lê o mesmo `window.APP_CONFIG`, que o fp-money.js lê deste bloco de dados no do base.html (não executa, vale com CSP estrita): Modo privacidade (opcional): `private="networth"` põe o patrimônio no grupo «Saldo do patrimônio» do modo privacidade (fp-privacy.js + tokens.css). O valor que o servidor escreve já sai com data-private, então não há lampejo do número nítido antes da ilha subir; a ilha marca o número, o sinal, a variação, o tooltip e os rótulos do eixo, e vira ponto de espiada (passar o mouse, focar ou segurar revela o cartão inteiro). Sem `private`, o HTML é exatamente o de sempre. {{ patrimonio(points=serie, private="networth") }} Segurança: com autoescape ligado (padrão do Jinja2Templates do FastAPI para .html) os atributos saem escapados, e o filtro `tojson` escapa <, > e & dentro do {%- endif %}
